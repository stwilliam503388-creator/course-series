# 案例5：蒙特卡洛仿真与项目工期风险评估 ★★★★☆

> 一个软件项目有 5 个串并行任务，用 Monte Carlo 仿真评估按期交付概率。

---

## 场景

你是某软件团队的项目经理。项目由 5 个任务组成，分为两个并行分支汇合后完成最终集成。

项目经理不能只给一个\"大概 20 天\"的估算——老板要的是：**"95% 的概率下，多少天内能交付？"**

### 项目任务结构

```
任务A (4天) ──→ 任务C (6天) ──→ 任务E (3天)
任务B (5天) ──→ 任务D (4天) ──↗
```

任务 A/B 并行，都完成后分别进入 C/D，C/D 都完成后进入 E。

### 三时估计

每个任务的工期不是固定值，而是三个估计值：

| 任务 | 乐观 | 最可能 | 悲观 |
|------|------|--------|------|
| A    | 3    | 4      | 7    |
| B    | 3    | 5      | 8    |
| C    | 4    | 6      | 10   |
| D    | 3    | 4      | 7    |
| E    | 2    | 3      | 5    |

老板问：
1. **项目总工期大概多长？**（均值和 P50/P90/P95 分位数）
2. **30 天内能交付的概率多大？**
3. **哪个任务是关键瓶颈？**（哪些任务最常成为关键路径）
4. **如果某个任务延期 20%，对总工期影响多大？**（敏感性分析）

## 建模

### 三角分布

用三时估计拟合三角分布：

```
PERT 均值 = (乐观 + 4×最可能 + 悲观) / 6
PERT 标准差 = (悲观 - 乐观) / 6
```

三角分布的概率密度函数：

```
f(x|a,m,b) = 
  2(x-a) / [(b-a)(m-a)],    a ≤ x ≤ m
  2(b-x) / [(b-a)(b-m)],    m ≤ x ≤ b
  0,                         其他
```

其中 a=乐观, m=最可能, b=悲观。

### 项目网络图

```
路径1: A → C → E
路径2: B → D → E

总工期 = max(A+C, B+D) + E

注意：不是简单的 max 再加 E——因为 E 必须等 C 和 D 都完成才能开始。
实际上 E 的 start = max(A+C, B+D)，总工期 = max(A+C, B+D) + E
```

## 方法

**Monte Carlo 仿真步骤：**

1. **定义任务**：5 个任务，每个含有三时估计
2. **定义网络依赖**：A→C→E, B→D→E（C 和 D 都完成后 E 才能开始）
3. **循环 N 次（N=10000）**：
   - 对每个任务，从三角分布采样一个工期
   - 按网络依赖计算各任务的最早开始/结束时间
   - 计算关键路径
   - 记录总工期
4. **分析结果**：
   - 总工期分布直方图
   - P50、P90、P95 分位数
   - 按期交付概率（P(工期 ≤ deadline)）
   - 每个任务出现在关键路径上的频次
   - 敏感性分析（每个任务延期 20% 时对总工期的影响）

## 验证标准

1. ✅ 总工期均值 ≈ PERT 公式的近似值（大数定律）
2. ✅ 任务 E 总是关键路径上的节点（因为它串联在最后）
3. ✅ 敏感性分析中，延期影响最大的任务与关键路径频次最高的任务一致
4. ✅ 仿真次数从 1000 到 100000 时，P95 分位数收敛（误差 ∝ 1/√n）
5. ✅ 关键路径频次统计：任务 A 或 B 中工期更长的那条路径更"关键"

## 关键洞察

1. **关键路径不是固定的。** 传统 PERT/CPM 用最可能工期算出一条关键路径，但在真实项目中，因为每个任务都有不确定性，哪条路径是"关键"其实是一个概率问题。任务 A 这次慢了，A-C-E 就是关键路径；下次任务 B 慢了，B-D-E 就成了关键路径。

   **就像两条高速公路进城**：平时 A 路 30 分钟，B 路 40 分钟——你觉得 B 是瓶颈。但 A 路有 20% 的概率堵车 1 小时，而 B 路很少堵。堵车的时候，关键路径就变了。只看"最可能"会错过这个风险。

2. **串行任务的"方差累加"效应比均值累加更可怕。** 总工期的方差随串行任务数量增加而累加——5 个串行任务，P95 可能比均值多 40%，而不仅仅是 10%。这就是为什么大型项目（50-100 个任务）几乎一定会延期：方差在大数定律下虽然使均值稳定，但分位数会越来越右偏。

3. **蒙特卡洛给了项目经理一个科学的沟通工具。** 不再说"项目大概 3 个月"，而是说"P50=3 个月，P90=3.5 个月，P95=3.8 个月"。老板可以基于自己的风险偏好选择承诺工期——保守的老板看 P95，激进的看 P50。这就是**概率驱动的项目管理**。

## 延伸

- 尝试不同的分布（Beta-PERT 分布代替三角分布）
- 加入资源约束（同一资源不能同时做两个任务）
- 用 Latin Hypercube Sampling 代替普通随机采样（更快收敛）
- 做"反向分析"：给定交付 deadline，多少资源才能达到 95% 的交付概率？
